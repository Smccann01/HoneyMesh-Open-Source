# Contributing

Open an issue for a proposed change or submit a pull request with a focused explanation and relevant test results. For a security vulnerability, use the private contact in [SECURITY.md](SECURITY.md).

Keep credentials, customer data, and production logs out of commits and test fixtures. Preserve license and attribution notices in files you change. New network signals or enforcement actions need tests for source authenticity, false positives, revocation, and safe failure.

A pull request is not a production release. The maintainers review the exact source, build artifacts, and support scope before publishing a release.
